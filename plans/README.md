## Findings considered and rejected

- **SettingsURIHandler `https` callback exfiltration**: `sendCallbackResponse`
  (`SettingsURIHandler.swift:1132-1178`) opens an arbitrary callback URL
  (scheme blocklist blocks `file/javascript/data/about/blob` + `x-apple-`,
  but allows `https`). A whitelisted app could exfil settings to an
  external server. **Rejected**: inside the authorized-sender threat
  model (the user explicitly whitelisted + code-signature-verified the
  app), and the settings data is not credential-sensitive. Not worth a
  plan; the scheme blocklist is the right gate.
- **Team-ID-only code-signature verification**
  (`SettingsURIHandler.swift:143-156`): verifies only the team
  identifier, not the full designated requirement. A sibling app from
  the same team would pass. **Rejected**: a known reasonable trade-off
  of team-ID-based auth; the prompt warns on unsigned apps. Not worth a
  plan.
- **Debug logging of window titles in `ScreenCapture.checkPermissions:35`**:
  logs other apps' menu bar window titles at debug level during
  permission check. **Rejected**: opt-in diagnostic (gated behind
  `diagLog.debug` which only emits when diagnostic logging is on); the
  standard cost of diagnostic logging in this category. Not worth a plan.
- **`SettingsSearchIndex` as a god-object** (740 lines): **Rejected** —
  mostly constant index data with a tiny operation surface; its
  purpose-built drift-guard tests (`SettingsSearchIndexTests.swift:68-141`)
  already cover the meaningful contract; no high-fan-in utility crush.
  (The ranking generalization in plan 030 is a separate, valid
  tech-debt win.)
- **`thaw-reset.sh` destructive `rm`**: **Rejected** — the script uses
  hardcoded quoted paths and deliberately omits `set -e` (correct for a
  reset script expecting failing `tccutil`/`defaults` calls). Reasonable
  safeguards; not worth a plan.
